## Repository layout

pnpm workspace + Turborepo monorepo. Node `^20.19.3` (see `.nvmrc`), pnpm required.

- `apps/dashboard` — SvelteKit app. Hosts **both** the teacher-facing dashboard (`src/routes/courses`, `src/routes/org`, `src/routes/home`, ...) and the student-facing LMS (`src/routes/lms`). Internal API routes live under `src/routes/api`. Package name: `@cio/dashboard`.
- `apps/api` — Hono service (`@hono/node-server`) for long-running work: PDF/video processing, email, notifications, S3/Cloudflare uploads. Exposes typed RPC via the `./rpc-types` export, which the dashboard imports as `@cio/api`. Package name: `@cio/api`.
- `apps/classroomio-com` — Marketing site (SvelteKit, Vite). Package name: `@cio/classroomio-com`.
- `apps/docs` — Public docs site. Package name: `@cio/docs`.
- `packages/shared` — Cross-app code (`plans`, `senja`). Imported as `shared`.
- `packages/course-app` — Course runtime/template package (has its own `src/*` workspaces declared in `pnpm-workspace.yaml`).
- `packages/tsconfig` — Shared `tsconfig` base. Root `tsconfig.json` extends `tsconfig/base.json`.
- `supabase/` — `config.toml`, `migrations/`, `seed.sql`, `data.sql`, `functions/`. Source of truth for the database schema.
- `cypress/` — End-to-end tests; root `cypress.config.js`.
- `docker/` — `Dockerfile.api`, `Dockerfile.dashboard`, `docker-compose.yaml` for self-hosting.
- `ai/prompts/lms-context.md` — Canonical short description of the product/stack; reuse when prompting other AI tools.

## Common commands

Run from the repo root unless noted. Turborepo orchestrates per-app scripts.

- Install: `pnpm i`
- Dev (all apps, host networking inside devcontainer): `pnpm dev:container`
- Dev (all apps, default): `pnpm dev`
- Dev a single app: `pnpm dev --filter=@cio/dashboard` | `--filter=@cio/api` | `--filter=@cio/classroomio-com` | `--filter=@cio/docs`
- Build all: `pnpm build`  (note: `@cio/dashboard#build` depends on `@cio/api#build` — see `turbo.json`)
- Lint all: `pnpm lint`
- Format: `pnpm format`
- Clean (also wipes every `node_modules`): `pnpm clean`

Tests are per-app, not at the root:

- Dashboard (Jest + svelte-jester + ts-jest, uses `tsconfig.test.json`): `pnpm --filter @cio/dashboard test` / `... test:watch`
- API (Vitest, Node env, globals enabled): `pnpm --filter @cio/api test` / `... test:coverage`
- Cypress e2e from repo root: `pnpm ci` (defaultCommandTimeout is 300000ms)

Single-test patterns: `pnpm --filter @cio/dashboard test -- path/to/file.test.ts -t "name"` for Jest; `pnpm --filter @cio/api test -- path/to/file.test.ts -t "name"` for Vitest.

Supabase (CLI must be installed; Docker required):

- Start local stack: `supabase start` (API :54321, DB :54322, Studio :54323, Inbucket :54324)
- Push schema to a linked remote: `pnpm supabase:push` (requires `PROJECT_ID` env)

## Architecture notes that aren't obvious from a single file

- **Two apps in one SvelteKit project.** The dashboard codebase serves teachers (`/courses`, `/org`, `/home`, ...) and students (`/lms/*`) from the same SvelteKit app. Layout files at `src/routes/+layout.*` and `src/routes/lms/+layout.svelte` partition the experiences. Don't assume new student features go in a separate app.
- **Dashboard → API typed RPC.** `apps/api/package.json` exports `./rpc-types` (`dist/rpc-types.{js,d.ts}`) and the dashboard depends on `@cio/api: workspace:*`. This is why `@cio/dashboard#build` depends on `@cio/api#build` in `turbo.json` — the dashboard cannot type-check until the API has emitted its `dist/`. If you change the API's public surface, rebuild API before dashboard typechecks will pass.
- **The API is Hono, not Express.** It runs via `@hono/node-server` from `apps/api/src/index.ts` on port 3002. OpenAPI is wired in via `configureOpenAPI(app)` and Scalar; routes live in `src/routes/`, services in `src/services/`. `tsc-alias` rewrites the `$src/*` path alias on build.
- **Auth, DB, and storage are Supabase.** Schema lives entirely in `supabase/migrations/` (timestamp-prefixed SQL). When adding a column or table, write a new migration file rather than editing existing ones. `seed.sql` / `data.sql` populate local-dev data.
- **Self-hosted vs hosted is a runtime flag.** `PUBLIC_IS_SELFHOSTED` is the only entry in `globalEnv` of `turbo.json`; treat it as the gate when adding paywalled or hosted-only features.
- **AI features use OpenAI Edge.** The dashboard depends on `openai-edge` and `ai`; course/lesson generation routes live under `src/routes/api/completion` and `src/routes/api/courses`. The API service does **not** call OpenAI — it handles media/email pipelines.
- **Devcontainer setup is automatic.** `.devcontainer/setup.sh` installs deps, starts Supabase, and writes `.env` files with the local Supabase keys on first launch. Prefer `pnpm dev:container` over `pnpm dev` inside the container so Vite binds `0.0.0.0`.
- **Default ports:** dashboard 5173, classroomio-com 5174, api 3002, docs 3000.
- **Local login for dev:** `admin@test.com` / `123456` against the seeded Supabase instance.

## Conventions worth respecting

- Always add new database changes as a new file in `supabase/migrations/` named `<UTCSTAMP>_<slug>.sql`. Existing migrations are immutable history.
- Path alias `$src` in `apps/api` and standard SvelteKit `$lib` in the dashboard. Don't reach across apps — share via `packages/shared` or the API's `rpc-types` export.
- Prettier (with `prettier-plugin-svelte`, `prettier-plugin-tailwindcss`) is the formatter; ESLint handles linting. Run `pnpm format` before pushing.
- The dashboard uses Carbon Components Svelte + TailwindCSS. `tailwind.config.js` and `postcss.config.js` live per-app.
