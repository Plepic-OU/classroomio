## Hard rules (learned the hard way)

1. **Alias must be a single token** — no spaces, no dots, no slashes, no brackets. The generator slugs the component key (e.g. `lib/components/Course` → `lib_components_Course`).
2. **Labels are quoted strings**. Escape any embedded double-quote.
3. **No `Lay_U/D/L/R` directives** — layout is determined by statement order. Put high-traffic elements first.
4. **No tags / sprites / `AddElementTag` / legends** — not implemented in Mermaid yet.
5. **Avoid more than ~30 elements per diagram** — readability and the layout heuristic both fall over.
6. **Boundaries can't be nested arbitrarily** — keep to one level (a `System_Boundary` around `Container`s, or a `Container_Boundary` around `Component`s).
7. **Markdown wrapping**: emit each diagram inside a fenced code block with the language tag `mermaid`.

## Rel labels

Keep labels short. Long labels overlap arrows. The default `"uses"` is fine when N edges collapse to one relationship; if you have richer semantic info, prefer verbs like `"reads"`, `"writes"`, `"renders"`, `"validates"`, `"publishes"`.
