# C4 model — ClassroomIO

Architecture documentation following the [C4 model](https://c4model.com/). The Layer-3 component diagrams and the database overview are generated by the `.claude/skills/c4-model` skill — invoke that skill in Claude Code to refresh them after any structural change.

| File | Layer | Contents |
| --- | --- | --- |
| [`context.md`](./context.md) | 1 — System Context | ClassroomIO as one box, with actors and external systems |
| [`containers.md`](./containers.md) | 2 — Container | Deployable units: dashboard, api, marketing, docs, Supabase |
| [`components-dashboard.md`](./components-dashboard.md) | 3 — Component | Inside `apps/dashboard`. Derived from AST. |
| [`components-api.md`](./components-api.md) | 3 — Component | Inside `apps/api`. Derived from AST. |
| [`database.md`](./database.md) | — | Supabase schema overview (tables, columns, FKs). Derived from `information_schema`. |
| `extraction.json` | — | Raw extraction output. Git-ignored. Used as input to the diagrams. |

## Regenerating

```bash
# First time only — installs ts-morph + tsx inside the skill directory
pnpm install --dir .claude/skills/c4-model --ignore-workspace

# Refresh extraction.json (apps/dashboard + apps/api)
pnpm --dir .claude/skills/c4-model exec tsx scripts/extract-components.ts

# Refresh database.md — requires `supabase start`
bash .claude/skills/c4-model/scripts/extract-database.sh > docs/c4/database.md
```

Then ask Claude Code to regenerate the diagrams in this folder from the refreshed `extraction.json` — see `.claude/skills/c4-model/SKILL.md` for the conventions to follow.

## Audience

These diagrams are primarily for AI context: a compact, accurate map of the system that fits in a model's context window. They are **not** meant to be the canonical visual architecture documentation for humans — they trade prettiness for correctness and freshness.
