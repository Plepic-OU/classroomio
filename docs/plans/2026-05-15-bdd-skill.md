# BDD Generator Skill

**Date:** 2026-05-15
**Status:** Draft
**Maturity:** POC
**Audience:** A developer working through [`2026-05-15-bdd-coverage-plan.md`](./2026-05-15-bdd-coverage-plan.md) who wants generation assistance.

This is the skill half of a two-part design. The coverage plan is the prerequisite — every scenario can be written by hand without this skill. The skill exists to **accelerate authoring**, not to be self-improving.

> Naming note: the original draft called this "self-improving." That term oversells what the skill does. It's an iterative BDD generator with a curated conventions cheatsheet — useful, not autonomous.

---

## 1. Layout

```
.claude/skills/bdd/
├── SKILL.md                    # Instructions + conventions, edited by humans
└── reference/
    └── svelte-carbon.md        # ClassroomIO-specific selector patterns
```

That's it. No `learnings.md` ledger (git history is the audit trail). No `scripts/propose-next-feature.ts` (the LLM does this from context). No `playwright-bdd.md` or `playwright-pointers.md` cheatsheets (Context7 MCP serves these on demand with no drift). When a convention emerges from a real failure, edit `SKILL.md` directly.

## 2. Three sub-commands

### `/bdd audit` — read-only gap report

1. Parse `docs/c4/bdd-flows.md` (flat checklist).
2. Glob `tests/e2e/features/**/*.feature`, list scenario names.
3. Cross-reference; flag flows checked-but-missing and scenarios-without-checklist-entry.
4. Recommend the next 1–3 flows to add, respecting phase order and data prerequisites (e.g. `create-course` before `add-lesson`).

### `/bdd extend <flow-name>` — generate one feature + steps

1. Read `SKILL.md` and `reference/svelte-carbon.md`. For Playwright/playwright-bdd API questions, query Context7 MCP.
2. Identify involved routes via `grep apps/dashboard/src/routes/`. Treat `docs/c4/layer3-dashboard.md` as a hint, not authoritative.
3. Reuse shared steps from `tests/e2e/steps/_shared/`; only generate new steps for novel verbs.
4. Write the feature file with the right auth tag (`@auth-admin` / `@auth-student` / `@auth-teacher` / `@no-auth`).
5. Present the diff. Do not run yet.

### `/bdd run [<glob>]` — execute and triage

1. `pnpm test:e2e` (root script already runs `bddgen` before `playwright test`). For a single feature: `npx bddgen --config tests/e2e/playwright.config.ts && npx playwright test --config tests/e2e/playwright.config.ts <glob>`. Globs match generated paths under `.features-gen/`, not source `.feature` files; prefer `--grep` on scenario name or tag.
2. On pass: tick the checkbox in `bdd-flows.md`.
3. On fail: classify (see §3) and propose a fix. Wait for user confirmation before applying.

### Invariant

Every change is diff-first, user-confirmed. The skill never silently rewrites scenarios that previously passed.

---

## 3. Failure triage

Three categories. Skill proposes a classification; user has final say.

- **App bug** — 500, route 404, DB constraint error, RLS-induced empty result where data is expected. Report to user with trace. Do not modify the test. Recommend filing an issue.
- **Test bug** — selector fragile, missing wait, assertion against dynamic value. Propose a fix that follows the determinism rules in the coverage plan.
- **Flake** — passes locally, fails in CI, or fails inconsistently. Re-run once. If 2nd fail, treat as a test bug. Never silently retry-loop.

If a fix is the kind of thing the next scenario will hit too (e.g. "Carbon Modal queries need `getByRole('dialog')` scoping"), edit `SKILL.md` or `reference/svelte-carbon.md` in the same PR. If not, just fix the one scenario.

---

## 4. When to stop using the skill

If `/bdd extend` consistently takes longer than writing a scenario by hand for the flow at hand, stop using it for that flow. The skill is a generation assist, not a forcing function.

Indicators the skill is earning its keep:
- Phase 2 scenarios go green on first or second run more often than not.
- Selector mistakes recur ≤ once across the phase (i.e. `reference/svelte-carbon.md` is getting better).

Indicators the skill is in the way:
- Same fix proposed twice for the same flow.
- Generated scenarios need >50% rewriting before passing.
- Skill keeps proposing selectors that violate Rule 5.

In either failure mode, edit `SKILL.md` to fix the root cause or revert to manual authoring for that area.
